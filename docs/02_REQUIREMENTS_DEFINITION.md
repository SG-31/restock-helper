## 1. Purpose（目的）

01 の要求を実現するために、システムが満たすべき条件（機能・品質・画面・データ）を定義する。

---

## 2. Scope（対象範囲）

01 の対象範囲のすべて（在庫入力、補充する数の計算、買い物リスト、買い物完了、管理品目、ログイン）。

---

## 3. Out of Scope（対象外範囲）

01 の対象外範囲と同じ。加えて、次の機能は作らない（将来の候補）。

- 消費の傾向のグラフ、リストの印刷
- 買い物リストから一部の品目だけを外す機能
- 品目ごとに「常にこの数だけ置く」という固定の数を決める機能
- 品目の種類ごとに管理方法を分ける機能（食品＝1週間分の消費量に合わせて補充する、日用品＝予備が1つ減ったら買い足す「予備1つキープ」）

---

## 4. Assumptions（前提条件）

- 在庫の入力は、品目ごとに週1回とする（同じ週に2回入力すると、平均の計算に影響する）
- 「買い物完了」は、表示された数をそのまま買ったものとして扱う（実際に買った数は入力しない）

---

## 5. Definition Details（定義内容）

### 5.1 Functional Requirements（機能要件一覧）

| ID | Feature Name（機能名） | Priority（優先度） | Details（詳細） |
|---|---|---|---|
| FR-001 | 在庫の入力と、補充する数の計算 | High | 品目ごとに今の在庫数を入力して保存すると、前回との差を消費量として記録し、補充する数を計算する。計算式は「直近4回の消費量の平均 × 1.5 − 今の在庫数」（端数は切り上げ、マイナスなら0） |
| FR-002 | 買い物共有画面 | High | 同一画面に「買い物リスト」（補充が必要な品目）と「買ってほしいもの」（リクエスト欄）の領域を分けて配置する。高齢者はこの画面から、買い物リストの確認と、「買ってほしいもの」の自由な文での追加・削除を行える |
| FR-003 | 買い物完了時の処理（買い物完了ボタン） | High | ①在庫数の更新：買い物で補充した数量を、現在の在庫数に自動で加算する<br>②リクエストのクリア：高齢者が追加した「買ってほしいもの」を自動で消去する |
| FR-004 | 管理品目の編集（登録・変更・削除） | High | 管理する品目の品目名・単位・初期在庫数の登録・変更・削除を行う。システムの構造をシンプルに保つため、品目の削除に伴い、これまでの消費記録も一括で消去する。誤操作によるデータの消失を防ぐため、削除の実行時には必ず確認の警告メッセージを表示する |
| FR-005 | ログインとトップ画面 | High | 共通のパスワード1つでログインする（30日保つ）。ログイン後のトップ画面から各画面へ移動できる |

### 5.2 Non-Functional Requirements（非機能要件）

| Type（種別） | Requirement（要件内容） |
|---|---|
| Performance（性能） | 応答性：日常の操作で快適な応答を確保する<br>コールドスタート：無料サーバーの仕様による、初回アクセス時の待ち時間を許容する |
| Availability（可用性） | 稼働条件：無料の公開サービスを前提とし、稼働の保証（SLA）は対象外とする |
| Security Requirement Level（セキュリティ要求レベル） | デモ用アプリとして基本的な認証機能を採用し、次の対策を行う（詳細は 03）<br>機密情報：パスワードなどの秘密情報は、環境変数で管理する<br>入力値の検証：サーバー側で入力値を検証する<br>CSRF対策：不正なフォーム送信を防ぐ |
| Maintainability（保守性） | ロジックの分離・テスト：計算処理や入力の検証を、UI・DBの処理から分離し、単体テストできる構成とする |
| Other（その他・UI/UX） | レスポンシブ対応：スマートフォンでも見やすいレイアウトとする<br>視認性：高齢者に配慮し、文字の大きさと読みやすさを確保する<br>誤操作防止：在庫を変更した行のハイライト表示と、保存・買い物完了・削除時の確認ダイアログを実装する |

### 5.3 Screen List（画面一覧）

| Screen ID（画面ID） | Screen Name（画面名） | Purpose / Overview（利用目的・概要） |
|---|---|---|
| SCR-001 | トップ | 各画面への入口。ログアウト |
| SCR-002 | 買い物リスト（高齢者用） | 補充が必要な品目の確認と、リクエスト（買ってほしいもの）の追加・削除。買い出しの際はヘルパーも参照する |
| SCR-003 | 在庫入力（ヘルパー用） | 在庫数を入力した後、買い物リストを表示する。買い物完了の操作で、補充量を在庫へ自動で加算する |
| SCR-004 | 管理品目一覧 | 登録済みの品目の一覧表示と、登録・変更・削除への入口 |
| SCR-005 | 管理品目の登録・変更 | 品目の登録と変更（同じ画面を使う） |
| SCR-006 | ログイン | 共通のパスワードによるアクセスの認証 |

### 5.4 API Overview（API一覧の概要）

本文書では対象外。理由：画面を返す Web アプリのみで、外部に公開する API を持たないため。

### 5.5 Data Overview（データ種別・件数規模の概要）

| Data Type（データ種別） | Estimated Volume（想定件数・規模） | Notes（備考） |
|---|---|---|
| 管理品目 | 1世帯あたり数十件まで | 品目名は重複不可 |
| 消費量の記録 | 品目ごとに週1件 | 計算には直近4件だけを使う |
| 買ってほしいもの | 数件 | 買い物完了で消える |

### 5.6 Mapping to Request Definition（要求定義との対応マッピング）

| User Story ID（ユーザーストーリー ID） | Functional Requirement ID（対応する機能要件 ID） |
|---|---|
| US-001 適正な購入数を把握する | FR-001 在庫の入力と、補充する数の計算 / FR-002 買い物共有画面 / FR-003 買い物完了時の処理 |
| US-002 管理する品目を変える | FR-004 管理品目の編集 |
| US-003 買ってほしいものを依頼する | FR-002 買い物共有画面 |

FR-005（ログインとトップ画面）は、特定のユーザーストーリーではなく、公開版を守るための非機能要件（5.2 のセキュリティ）と、各画面への入口のために設ける。

## 7. Handoff to Detail Design（詳細設計への引き継ぎ）
